# 《崩坏：星穹铁道》系统拆解

以连续阅读为主的系统策划作品页，分析范围为原稿撰写时期的 3.5 版本。

## 内容维护

- 修改 `content.md` 中的正文。
- 图片保存在 `assets/`，在正文中使用相对路径引用。
- 第一个二级标题是副标题，后续二级标题自动生成章节目录；三级标题用于章内小节。
- 二级标题的章节地址保持固定，三级标题按小节编号生成锚点。桌面目录显示当前章小节，移动端目录可随时展开。
- 表格正文只维护一份；构建时自动生成桌面表格与移动端纵向条目。
- `styles.css` 管理阅读样式，`reader.js` 管理目录定位。构建后内联，无需额外脚本请求。
- `draw_figures.py` 生成流程图的桌面和手机版本（需 Python、Pillow 和微软雅黑字体）。`share-card.html` 是分享封面的可编辑版式。
- 发布前运行 `npm install` 和 `npm run build`，更新后的网页会自动写入 `docs/`；提交正文及生成的网页文件即可更新内容。

## 网页发布

GitHub Pages 使用 `main` 分支的 `/docs` 目录。网页只依赖静态文件，无需访客登录。

作品的独立路径是 `/game_present/hsr/`。根目录暂时跳转到作品，后续可以换成个人主页，作品路径不变。

## 目录

- `content.md`：网页正文。
- `build.mjs`：生成页面和目录。
- `verify.mjs`：使用 Playwright 检查多种屏幕尺寸、目录操作及正文完整性；可传入本地或线上地址。
- `assets/`：正文使用的图片。
- `docs/`：GitHub Pages 发布文件。

网站最终访问地址以 GitHub Pages 部署成功后的结果为准。
